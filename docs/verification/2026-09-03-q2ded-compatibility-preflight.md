## Транспортный пробник

Использован существующий бинарный файл:

```text
linux/build-release/q2dz-webrtc-gateway
SHA-256 7c7a99a458bf16cf3be5af221cff63383f58bbe47a0a82eb5e0b43bbbd710c8b
WebRTC-NET lock entry 1b8c145b8fb00e8a1599ec311118cd38aad44e7a
```

SHA-256 связывает вывод с точным исполняемым файлом. Lock entry приведена как
нормативная зависимость репозитория; отдельная воспроизводимая пересборка этого
старого пробного бинарного файла в этом gate не выполнялась.

Он был запущен с одним текущим exact dedicated alias и полным агрегированным
RTC payload. Результат:

```text
GATEWAY_READY: 1
OOB ping -> ack: PASS, 7 bytes
OOB status: PASS, 333 bytes
udp_to_webrtc: 2
webrtc_to_udp: 2
oversized_udp_drops: 0
oversized_transport_drops: 0
```

Это доказывает alias lookup, WebRTC transport и настоящий ответ Quake II
`status`. Проверка не объявляется доказательством входа в карту: такой live
gate выполняется на собранной поставке после изменения кода.

Gateway штатно остановлен. Фоновых q2dz gateway после проверки не осталось.
Временные файлы с сетевой конфигурацией удалены.

## Ограничение свидетельства

Точный UTC-интервал сетевого пробника отдельно не был сохранён; известна дата и
время публикации отчёта. Это снижает точность временной корреляции, но не меняет
проверенные значения и не является причиной повторно передавать действующие
учётные данные через тестовый путь.

## Решение

Режим совместимости допускается к реализации:

- `q2ded room` используется как точный alias только после exact lookup;
- используются все свежие валидные RTC rows с пределами `16/65535`;
- лимит продукта — три dedicated и две обычные комнаты;
- gateway transport не изменяется.
