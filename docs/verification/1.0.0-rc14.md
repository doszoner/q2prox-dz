## Task 4 Windows shared WebView2 transport

Дата: 2026-09-04. Реализован один WebView2/WebRTC-NET runtime с динамическими
target maps, отдельными loopback sockets и OOB probes. Native host принимает
v1 single-target JSON и bounded HUB/2 stdin; WebView callbacks остаются на STA
thread. Alias lookup использует точный `=alias`, concrete PeerId закрепляется
через reverse map, повторный concrete peer отклоняется; WebRTC-NET callback
generation token отбрасывает late callbacks после замены query. Tagged UDP и target
state сообщения проходят strict targetId/size/field validation; targetId
пересекает bridge как canonical decimal string без потери uint64; credentials и
ICE/room JSON не выводятся в diagnostics. HUB/2 ICE generation также пересекает
bridge как canonical decimal string и сравнивается в странице через BigInt;
при пустом наборе targets глобальный сбой сохраняет режим HUB/2 и выдаёт
`Q2DZ/HUB/2 FATAL`, тогда как v1 сохраняет `Q2DZ/1`.

До page-ready очередь HUB/2 принимает burst из ICE и 256 bounded PUT (плюс
STOP), после чего STA drains не более 32 команд за tick. Receive scheduler
ограничивает scan до 64 и delivery noisy peer до 8 за tick с round-robin между
target queues; socket/select и recvfrom failures закрывают только затронутый
target. Legacy v1 сначала получает loopback socket для target 1 и сохраняет
`Q2DZ/1` READY/FATAL/CLOSED output.

TDD RED был получен до реализации: Node suite падал на отсутствующем
`createTargetRegistry`, native bridge compile падал на отсутствующих tagged API;
после реализации оба контура прошли.
