# q2prox-dz 1.0.0-rc6 verification

Date: 2026-08-23

> **Post-verification field update:** subsequent community testing found a
> confirmed `3zb2` launch-order defect and a Windows-only approximately 1 Hz
> gameplay problem. The latter currently has a strong but unconfirmed WebView2
> background-timer hypothesis. Both Windows artifacts are blocked for wider
> redistribution pending correction and retest. See
> [Windows field-test findings](2026-08-23-windows-field-test-findings.md).

## Verdict

| Delivery | Verdict | Evidence boundary |
|---|---|---|
| Linux x86_64 package | PASS | Exact package installed locally; real Dos.Zone `q2dm1` join, movement, fire, owner close, normal exit and hard coordinator kill passed. No owned process, session-directory or credential-shaped residue remained. |
| Windows x64 portable ZIP | BLOCKED after field testing | The original clean-VM gate passed, but later testers exposed a confirmed game-selection defect and an open Windows-only approximately 1 Hz transport problem. |
| Windows x64 setup ZIP | BLOCKED after field testing | Installation gates remain valid, but setup shares the affected coordinator and WebView2 gateway; installed-copy gameplay was already incomplete. |

The Windows RTC catalog defect found during the first clean-VM run was fixed before the artifacts below were built. `Get-Q2DzSelectedTransport` had wrapped an already non-enumerated `Object[]` a second time. The regression test now covers a multi-row, non-enumerated RTC response; the final catalog suite passed all 21 shared cases.

testing supersedes the original Windows release conclusion: Windows portable
and setup are suitable only for controlled diagnostic testing until the issues
linked at the top of this document are corrected and the packaged live gates
are repeated. Room-hub/Custom-source work is a later gate and is not implied by
this result.
