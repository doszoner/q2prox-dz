# q2prox-dz 1.0.0-rc12: Windows Custom source

Дата проверки: 2026-08-31.

## Итог

Windows `1.0.0-rc11` не следует передавать новым тестировщикам: при корректно
заданном локальном источнике вкладка `Custom` могла оставаться пустой.
Пользовательский CFG и параметр `cl_serverbrowser_custom_source` не являлись
причиной.

В `1.0.0-rc12` исправлено преобразование ответов Dos.Zone в PowerShell.
И диагностическая сборка, и заново распакованный итоговый portable ZIP в
Windows 11 VM показали комнаты, получили обычный Quake II `status` и
подключились к `q2dm1`.

## Воспроизведение rc11

Проверялся заново распакованный архив:

```text
q2prox-dz-1.0.0-rc11-windows-x64-portable.zip
SHA-256 689195110b2ec49c5e059af2418b65d97372cd06b2d4a2676eb31b40b9dc1adc
```

Порядок проверки:

1. Q2PRO-X был запущен только через `Run.cmd`.
2. `cl_serverbrowser_custom_source` содержал локальный адрес вида
   `http://127.0.0.1:<порт>/servers`.
3. В каталоге Dos.Zone находилась готовая комната Quake II с картой `q2dm1`.
4. После `Join Online` → `Custom` → `Refresh` список оставался пустым.
5. `q2dz-session.exe` работал, но процесс шлюза комнаты не запускался.

Ручное добавление источника в CFG не могло исправить этот
случай: Q2PRO-X уже получил правильный адрес, а локальный источник действительно
возвращал пустой список.

## Причина и исправление

Функция `Get-Q2DzJson` в `windows/product/catalog.ps1` возвращала значение с
`Write-Output -NoEnumerate`. В одном случае корневой объект каталога превращался
в список из одного элемента, а в другом корневой массив RTC получал лишний
уровень вложенности при прохождении через блок загрузки. Строгая проверка
отвергала данные, после чего launcher безопасно оставлял оба слота комнат
пустыми.

Исправление оставляет обычное поведение конвейера PowerShell:

```powershell
Write-Output $value
```

Объект каталога остаётся объектом, а элементы корневого массива RTC собираются
вызывающим кодом в плоский массив. Отдельными тестами закреплены оба случая,
включая прохождение массива через фактический блок `FetchJson`.

## Порядок проверки для пользователя Windows

1. Полностью закрыть Q2PRO-X.
2. Распаковать новый portable ZIP в новую пустую папку. Не копировать его поверх
   старой версии.
3. Открыть файл `VERSION`. Ожидается `1.0.0-rc12`.
4. Запустить именно `Run.cmd` из этой папки. При первом запуске выбрать
   установленный `Q2PRO-X.exe`.
5. Подождать до 15 секунд, пока launcher впервые опросит каталог.
6. Открыть `Join Online` → `Custom` и нажать `Refresh`.
7. При наличии готовой комнаты должна появиться строка с именем сервера, картой,
   числом игроков и ping. Выбрать её и подключиться.

`Run.cmd` сам задаёт временный локальный HTTP-источник. Добавлять
`cl_serverbrowser_custom_source` в `q2config.cfg` или указывать файл не нужно.
Комнаты опрашиваются launcher примерно раз в 15 секунд; сам Q2PRO-X перечитывает
полученный список после кнопки `Refresh`.

Если список остаётся пустым, для сравнения достаточно прислать:

1. содержимое файла `VERSION` из запущенной portable-папки;
2. вывод команды `cl_serverbrowser_custom_source` в консоли Q2PRO-X;
3. снимок `Custom` после `Refresh` при заведомо существующей готовой комнате;
4. подтверждение, что Q2PRO-X был запущен через `Run.cmd`, а не обычным ярлыком.

Ожидаемый вывод cvar — локальный адрес `http://127.0.0.1:<порт>/servers`.
Порт выбирается при каждом запуске и не должен совпадать между компьютерами.
