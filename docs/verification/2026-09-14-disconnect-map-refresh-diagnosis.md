# Обрывы после смены карты: диагностика 2026-09-14

Публичная сокращённая версия исходного отчёта; персональные идентификаторы,
серверные журналы и частные пути исключены. Проверки относятся к исходной
дате и не повторялись при публикации документа 2026-10-18.

Изменение только `map` в каталоге вызывало DROP/PUT той же комнаты. Coordinator
создавал новый target, gateway закрывал WebRTC и UDP socket, затем получал
новый локальный порт. Работающий Q2PRO-X оставался на старом endpoint.
Это воспроизведено на настоящем Linux launcher/coordinator с тестовым
transport; Windows-планировщик воспроизведён PowerShell на Linux. Это
контролируемые проверки жизненного цикла, не Windows gameplay E2E.

В двух предоставленных эпизодах смена карты предшествовала обработке нового
каталога, reset канала и примерно трёхсекундному клиентскому timeout.
В одном эпизоде refresh пришёл примерно через 118 секунд после смены карты:
так обрыв мог выглядеть как произошедший уже во время игры. Источник этой
задержки не установлен. Исторические HUB-команды и HTTP-снимки не записаны;
отнесение именно этих обрывов к воспроизведённому механизму — вывод по
корреляции и коду, а не запись DROP в момент инцидента.

Временные метки исходных серверных логов с `Z` — UTC; для Эр-Рияда прибавляются
три часа. Настройка timezone самого хоста из этого не следует.

Дефект исправлен в `6f3fc10`, вошёл в rc17: map-only изменение не пересоздаёт
маршрут, content-check недоступной карты исключает только эту комнату.
[Исправление и проверки](2026-09-14-catalog-map-refresh-fix.md),
[архивы rc17](1.0.0-rc17.md).
Причина конкретного временно пустого списка этим отчётом не доказана;
последующее [исследование каталога](../research/2026-10-01-rooms-vanish.md)
не следует ретроспективно считать доказательством того же инцидента.
