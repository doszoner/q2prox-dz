# Linux: пустой Custom при запуске rc15

Проверка 2026-09-05 на локальной Linux-машине, Q2PRO-X 1.5 от 2026-08-25
через Wine. Исходная установка и репозиторий: `1.0.0-rc15`,
ветка `feat/dedicated-compat`, исходный коммит `0426781`.

## Причины и исправления

1. Установленный `q2dz-launch` передавал координатору
   `--gateway .../q2dz-managed-gateway`. Это старый однокомнатный адаптер.
   Координатор уже запускает общий транспорт по протоколу HUB/2.
   При живом запуске адаптер дважды завершился с
   `--legacy and --adapter are required`, после чего появились
   `HUB_GATEWAY_STOP reason=gateway-control-eof` и
   `HUB_TRANSPORT_DISABLED reason=gateway-control-eof`.
   HTTP-источник оставался пустым. Исправлен выбор по умолчанию:
   `q2dz-webrtc-gateway`.
2. `reconcile_targets()` сравнивал полные JSON-конфигурации, включая
   `iceServers`. Два последовательных запроса к действующему каталогу
   дали три команды DROP; единственным изменившимся полем было
   `iceServers`. Поэтому каждые 15 секунд соединения создавались заново.
   Теперь сравнение исключает ICE, который передаётся отдельно.
   Свежая конфигурация сохраняется для последующего восстановления.
   Изменение alias, карты или других параметров комнаты по-прежнему
   вызывает её замену.

Исправления внесены в `linux/tools/q2dz-launch` и установленный
`~/.local/share/q2dz/bin/q2dz-launch`. Их SHA-256 совпадает:

```text
a5a4286a3672e988d7416598bdd72fdf4702593cfc6652cc99c755ef24bc519d
```

## Проверки

- Два новых регрессионных теста сначала воспроизвели ошибки, затем прошли.
- `python3 -B -m unittest discover -s linux/tests -p test_launcher.py`:
  22 теста, PASS.
- `ctest --test-dir linux/build-release --output-on-failure -j2`:
  7/7 PASS, включая проверки жизненного цикла и прямого HUB/2-транспорта.
- Проверка установленного `q2dz-webrtc-gateway` через
  `linux/tests/test_direct_gateway.py`: PASS.
- Повторный живой опрос каталога после исправления: 3 комнаты, 0 DROP
  при обновлении ICE.
- В первом исправленном запуске HTTP-источник вернул три разных локальных
  адреса. В самом Q2PRO-X открыто меню Custom: три строки серверов.
  COMMUNITY FFA и q2dm1[SPB] отдали карту и число игроков;
  строка DUEL отображалась как `badinfo`. Причина этого ответа не установлена.
- В следующем запуске HTTP-источник устойчиво содержал два адреса;
  полнота списка при каждом запуске пока не доказана.
- Через этот запуск выполнено подключение под нейтральным именем `Client1`:
  `Requesting challenge`, `Requesting connection`, `Client1 entered the game`.
  Карта визуально загружена; соединение сохранялось несколько обновлений
  каталога. Автоматический ввод движения/стрельбы недостаточно подтверждён,
  поэтому отдельный PASS этих действий не заявляется.
- Отдельный ограниченный запуск установленного общего транспорта получил
  `READY` для всех трёх действующих серверов:

```text
1 community-ffa.spb: peer=1853642885
2 duel.spb:          peer=1681197096
3 q2dm1.spb:         peer=1766010406
READY_COUNT 3
```

## Свидетельства и граница результата

Сохранённые снимки и сокращённый журнал:
`/path/to/DosZone/q2prox-dz-local-evidence/2026-09-05-empty-custom/`.
Файлы: `q2dz-fixed-browser.png` (три строки Custom),
`q2dz-live-join.png` (загруженная карта),
`q2dz-final-custom-complete.png` (конечный список), `live-summary.log`.
Журнал повторного запуска: `/tmp/q2dz-rc15-fixed-live-2.log`.
Это временные локальные свидетельства; целиком публиковать журналы без
проверки содержимого нельзя.

Один пробный процесс завершился при прерывании инструментальной сессии.
Дальнейший запуск отделён от терминала через временную пользовательскую
службу systemd. Остановка всей службы одновременно прервала владельца и
его guardian и дала `guardian cleanup failed`; это не выдано за проверку
нормального выхода игры.

Исправления относятся к локальной Linux-установке и исходникам. Нативные
библиотеки и EXE не пересобирались: изменён только Python-запускатель.
Архивы rc15 не обновлены. Windows в этом прогоне не проверялась;
там также требуется проверить сравнение конфигураций при обновлении ICE.
В последнем свежем запуске источник вернул четыре устойчивых адреса,
а Q2PRO-X после окончания опроса показал четыре сервера: три dedicated
и появившуюся P2P-комнату. Получены имена игроков q2dm1[SPB].
Игра оставлена открытой на Custom; установленный запускатель содержит
обе правки. Сохранённое имя пользователя `ezh` проверено после теста.

Остаточные вопросы: неполный список в одном предыдущем повторе
и `badinfo` у DUEL. Последний полный список не доказывает устранения
непостоянных транспортных отказов.
