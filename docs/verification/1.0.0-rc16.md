и исправлена утечка `$LASTEXITCODE=17` из fake-checker теста в release caller.
Проверен вызов сборщика, а не только строка PASS:

```powershell
$global:LASTEXITCODE = 0
& ./windows/product/tests/catalog.tests.ps1
if ($LASTEXITCODE -ne 0) { throw 'Catalog contract failed' }
```

Фактический результат: `POST_CATALOG_LASTEXITCODE=0`.
Тест восстанавливает предыдущее значение или отсутствие переменной.
Отсутствующий executable также проверен: до исправления тест получал сырой
`CommandNotFoundException` с путём, после — только безопасное
`content checker execution failed`. Повтор catalog/launcher stdin и
release-caller проверки после этой правки: PASS.

До исправлений: catalog тест падал на `map content check failed`, Node
давал 28 PASS / 1 FAIL на порядке UDP JSON, coordinator parser отвергал
FATAL. Независимый исходный ICE probe выдавал `targets=5, drops=5` при
изменении только ICE. Эти результаты не подменяются успешными тестами
отдельных старых компонентов.

Добавлен Windows lifecycle сценарий глобального FATAL: диагностический
stage/code, очистка source, один перезапуск gateway, живой Q2 и cleanup.
Сценарий выполнен в Windows: `PASS global-fatal (exit=0)`.

## Граница поставки

Только новые Windows portable/setup ZIP и соседние SHA-256. Старые rc15
артефакты не перезаписываются; Linux не пересобирается и не переименовывается.
Исходники Quake II, WebRTC-NET и production services не меняются.

Для широкого распространения по-прежнему нужны отдельные exact-client,
gameplay и Authenticode gates из [release contract](../RELEASE.md).
Синтетические тесты и READY не доказывают вход в игру.
