# Проверка Windows 1.0.0-rc16

Дата: 2026-09-08. Windows-only correction candidate; Linux остаётся rc15.

Основание: [разбор Windows 11](2026-09-08-windows11-empty-custom-review.md).
План: [адресные исправления](../superpowers/plans/2026-09-08-windows-empty-custom-fix.md).

## Состояние проверки

Исходники исправлены; локальные регрессионные проверки пройдены.
PASS Windows-сборки и поставки не заявлен: новые ZIP не созданы.
База — `feat/dedicated-compat` на `5db6275`.
Проверки исходного дефекта и исторической rc15 находятся в отдельном разборе;
они не являются результатом тестирования rc16.

## Локальные проверки исправлений

Выполнены на Linux-хосте, не в Windows VM:

| Проверка | Результат |
|---|---|
| PowerShell catalog | PASS, 40 shared cases и локальные регрессии |
| PowerShell launcher stdin | PASS |
| Node transport page/protocol | 29/29 PASS |
| CMake coordinator core/content checker | 2/2 CTest PASS |
| C++ WebView bridge protocol | PASS, g++ build/run |
| Linux unit binary, запуск из `linux/` | PASS |
| Python Linux launcher | 22/22 PASS |
| `git diff --check` | PASS |

Ключевые регрессии: одна отсутствующая карта не скрывает соседей; смена
карты исключает лишь соответствующий retained target, возвращение карты
вновь допускает комнату; ICE-only изменение не создаёт DROP; фактический
JS sender выдаёт ожидаемый native decoder порядок полей; глобальный FATAL
не требует id, безопасные stage/code сохраняются.

Checker различает 0/3/прочие коды выхода. В процессе проверки обнаружена
и исправлена утечка `$LASTEXITCODE=17` из fake-checker теста в release caller.
Проверен вызов сборщика, а не только строка PASS:

```powershell
$global:LASTEXITCODE = 0
& ./windows/product/tests/catalog.tests.ps1
if ($LASTEXITCODE -ne 0) { throw 'Catalog contract failed' }
```

Фактический результат: `POST_CATALOG_LASTEXITCODE=0`.
Тест восстанавливает предыдущее значение или отсутствие переменной.
Отсутствующий executable также проверен: до исправления тест получал сырой
`CommandNotFoundException` с путём, после — только безопасное
`content checker execution failed`. Повтор catalog/launcher stdin и
release-caller проверки после этой правки: PASS.

До исправлений: catalog тест падал на `map content check failed`, Node
давал 28 PASS / 1 FAIL на порядке UDP JSON, coordinator parser отвергал
FATAL. Независимый исходный ICE probe выдавал `targets=5, drops=5` при
изменении только ICE. Эти результаты не подменяются успешными тестами
отдельных старых компонентов.

Добавлен Windows lifecycle сценарий глобального FATAL: диагностический
stage/code, очистка source, один перезапуск gateway, живой Q2 и cleanup.
Этот сценарий пока НЕ выполнен: требуется Windows GuestControl.

## Независимое ревью

SPEC PASS / QUALITY PASS для коммита исходников после исправления ошибки
запуска checker. Блокирующих замечаний к изменённому production-коду нет.
Повторные локальные проверки перечислены выше; этот verdict не является
PASS Windows build/lifecycle/package или успешного запуска у пользователя.

## Граница поставки

Только новые Windows portable/setup ZIP и соседние SHA-256. Старые rc15
артефакты не перезаписываются; Linux не пересобирается и не переименовывается.
Исходники Quake II, WebRTC-NET и production services не меняются.

Для широкого распространения по-прежнему нужны отдельные exact-client,
gameplay и Authenticode gates из [release contract](../RELEASE.md).
Синтетические тесты и READY не доказывают вход в игру.
