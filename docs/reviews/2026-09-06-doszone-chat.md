Дата: 2026-09-06. Reviewer: **gpt-6-astra, high**.
База проверки: `c7277cd`, рабочий checkout `q2prox-dz-dedicated-compat`.

## Продолжение исполнения: проверка доступных механизмов

После возобновления Goal выполнен ограниченный аудит установленного клиента
исполнителем Luna Max. Astra high проверил его по первичным материалам:

1. **Spec REVISE:** ссылка на `CL_Connected` в меню оказалась неверной — это
   строка EXE. Описание асинхронного перевода в руководстве было ошибочно
   названо доказанным безопасным callback. Вывод о невозможности использования
   custom translation URL был сильнее фактически выполненной проверки.
2. Исправлены источник и формулировки: документация, строки бинарника и
   непроверенные гипотезы теперь отделены от результатов запуска.
3. Повторное **Spec PASS**, затем **Quality/clarity PASS**. Проверены также
   актуальный отчёт состояния и дополнение к исследованию службы.

Это принятие результатов ограниченного аудита, не реализации чата.
Клиентский исходник/доступное расширение и собственная программная отправка
остаются нерешёнными частями. Task 4 реализован в 9 code/ADR files: Linux CTest
5/5 PASS за 21,8 с; Windows corrected archive дал build, CTest 2/2, Node 8/8
и полный matrix PASS.
Отдельного согласования C3 не требуется.
Linux 256-fixture выявил только несовместимость buffered `readline`/`select`;
`unbuffered dup stdin` ограничен fixture, обычный timeout и один 256-batch не
менялись.
Финальный core test 2/2 и process cleanup также PASS; VM сохранена, running VMs
отсутствуют.
По Task4 первый Astra SPEC был REVISE из-за Windows startup marker, header
values, 256 parity/generation/case/fields assertions и ADR; после исправлений
повторный SPEC PASS и отдельный QUALITY PASS. Финальный queue-fix получил
отдельный REVISE по валидности/порядку теста, затем SPEC PASS и QUALITY PASS;
minor core test подтвердил valid heartbeat/full-byte order.
Текущие результаты исполнения: [единый отчёт](../verification/doszone-chat-admission.md).

## Редакция 2: штатная горячая клавиша и ввод

Дизайн переработан по уточнению пользователя: клавиша в управлении клиента,
штатный режим сообщения, Enter освобождает ввод до сетевого ответа, Esc
отменяет; глобальные hooks и синтетические нажатия не нужны. Добавлены правила
удержаний, автоповторов, потери фокуса, смены комнаты и хранения только в памяти.
Отправка собственным кодом остаётся исследовательской задачей; старые C1/C2/C3
не являются поводом повторять проверки отрисовки или требовать новый API заранее.

Последовательное ревью Astra high: **technical-premortem PASS для дизайна**,
затем **ponytail-review PASS**, обязательных правок нет. Исследование luna_max
содержит первичные ссылки на установленное меню и открытый механизм ввода.
Это принятие проекта поведения, не утверждение доступности исходников клиента,
готового отправителя или пользовательского пакета. Прежние вердикты ниже — история редакции 1.

План редакции 2 подготовлен luna_max и проверен Astra high последовательно:

1. Technical-premortem **REVISE**: Task 1 преждевременно требовал mapping из
   Task 4; запрет повторной отправки ошибочно распространялся на чтение.
2. Исправлено: Task 1 устанавливает событие соединения/endpoint/epoch,
   интеграция с mapping проверяется позже; чтение возобновляется с задержкой
   2/4/8/15 секунд, отправка с неизвестным исходом не повторяется.
3. Повторный technical-premortem **PASS**, затем ponytail-review **PASS**.

План принят как последовательность исследования и доведения; полный чат,
клиентский патч и новые пакеты не выдавались за выполненные.

## Дополнение: практическая проверка клиента

После разрешения клиентских правок выполнен изолированный GUI-опыт под Wine.
Последующее ревью **Astra high: PASS для практических выводов**, не для
готовности полного чата. Ревьюер проверил снимки, меню, журнал и совпадение
хеша тестового EXE с исходным. Подтверждены `field → cvar → draw` поверх `base1`
и точная строка `Client1: Привет; ё`.

Для этих уже работающих возможностей не нужны исходники или новый API.
Внешнее обновление, передача введённого текста помощнику и кириллический ввод
ещё не доказаны; это не доказательство невозможности. Следующая проверка —
конкретный безопасный двусторонний обмен клиент/помощник, без исполнения
сообщений и имитации клавиш. [Отчёт и свидетельства](../research/2026-09-06-doszone-chat-client.md#практическая-проверка-установленного-клиента).

Остальные разделы ниже фиксируют первоначальное ревью до этих опытов.

Актуальный отчёт допуска затем сведён luna_max в один документ без повторения
старых остановок. Astra high: spec REVISE (четыре уточнения границ опыта и
разрешений), после исправлений **spec PASS**, затем **quality/ponytail PASS**.
Эти вердикты относятся к отчёту, не к реализации чата. Полный клиентский путь
и поддерживаемая нативная отправка пока не доказаны; bounded audit указывает на
необходимость exact client source/build либо equivalent documented extension.

## Последовательность проверок и внесённые правки

1. **Дизайн — technical-premortem, REVISE.**
   - ADR 0004 разрешает только `/servers`; второй GET требовал явного допуска
     изменения договора. Добавлен C3, действующий ADR не переписан.
   - Однократного mapping недостаточно при закрытии комнаты. Указаны discovery
     через точный loopback source, отдельный polling раз в секунду, deadline
     две секунды и потеря права отправки после трёх секунд без свежего mapping.
     `Refresh` меню не используется как сигнал активной комнаты.
2. **Повторный technical-premortem, REVISE → PASS после уточнения.**
   - Строгий Host с портом сломал бы существующий Windows fake client, который
     отправляет Host без порта. Новые Host/Origin проверки ограничены новым
     `/q2dz/rooms`; прежний `/servers` сохраняет разбор и поведение.
   - Исследования клиента и службы прочитаны ревьюером. Неподтверждённые
     интерфейсы оставлены условиями допуска, не объявлены реализованными.
3. **Дизайн — ponytail-review, две правки → Lean already. Ship.**
   - Убрано автоматическое предложение свободной клавиши. Новое действие
     назначается через штатное меню и не меняет существующие бинды.
   - Убрано неиспользуемое поле `revision` mapping; остаются version,
     session/target и проверка свежести.
4. **План — technical-premortem, REVISE → PASS после правок.**
   - Общий запрет отправок до допуска конфликтовал с разрешённой проверкой
     самого C2. Разделены несогласованные/production-действия и ограниченные
     проверки после явного разрешения и получения договора/окружения.
   - Source tree не является blanket-требованием для уже документированного
     API, но для native editor/HUD нужен exact source/build либо equivalent
     documented extension; mapping может реализовываться независимо.
5. **План — ponytail-review: Lean already. Ship.**
   - Дополнительных сокращений не потребовалось.
   - GOAL проверен на согласованность: внешние условия не скрыты, отчёт о
     блокере не равен завершению полного чата.

Все проходы выполнены последовательно одним reviewer Astra high с правками
между соответствующими проходами. Повторный PASS относится к исправленным
документам, не к готовности полного production-чата.

## Фактически проверено в этой работе

- Прочитаны текущие coordinators/launchers, source handler, ADR, правила
  безопасности, старое исследование и C#-пример.
- Исследованы exact установленный клиент, MANIFEST, руководства, открытый
  Q2PRO и официальная документация Q2PRO-X. Отсутствие подтверждённого
  интерфейса не приравнивается к доказательству отсутствия любого private API.
- Прочитаны текущие публичные bundle/iframe Dos.Zone и ограниченный снимок
  каталога. Authenticated mutation, создание участника и отправка не проводились.
- `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s browser-chat -p 'test_*.py' -v`
  из родительского каталога: **3/3 PASS**. Это старые тесты чтения/фильтрации,
  не проверка нового HUD, dedicated-чата или отправки.
- `validate_goal.py --profile platform` для нового GOAL: **2609 символов**,
  механическая проверка PASS. Предупреждения поиска английских слов вручную
  проверены: исход, доказательства, границы, итерации и остановка описаны
  по-русски. Линтер не заменяет эту смысловую проверку.
- Проверены шесть документов: локальные Markdown-ссылки существуют,
  whitespace-проверка не обнаружила ошибок. Текущий рабочий tree содержит
  параллельные Task 4 изменения; этот review их не редактировал.

Ни игра/Wine, ни VM не запускались в рамках этого review. Task 4 coordinator
изменения и сборочные результаты зафиксированы выше; Q2PRO-X, Quake-сервер и
WebRTC/HumbleNet этим review не изменялись. Commit/push не выполнялись.

## Минимальное продолжение

1. **Client/Q2PRO-X:** exact source/build или equivalent documented extension
   для native editor/HUD, после завершения bounded audit.
2. **Dos.Zone:** собственная native-регистрация и отправка остаются
   неустановленными в границах SECURITY; browser PASS это не заменяет.
3. **Task 4:** mapping, core test и process cleanup PASS; отдельного C3 approval
   для внутреннего mapping не требуется.

После этого задача 5 плана заменяет условные этапы точными кодовыми шагами и
повторяет ревью до начала реализации. До этого возвращаться к F1/CFG,
подмене browser identity или анализу игрового протокола не следует.
