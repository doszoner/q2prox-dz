# Dedicated-серверы Dos.Zone во вкладке Custom Q2PRO-X

- **Статус:** принят для реализации в режиме совместимости
- **Дата:** 2026-09-03
- **Область:** Windows и Linux поставки q2prox-dz
- **Основание:** [исследование](../research/2026-09-03-dedicated-server-connectivity.md), [ADR 0004](../adr/0004-q2pro-x-custom-source-room-hub.md)

Документ уточняет ADR 0004. Владелец продукта 2026-09-03 разрешил режим
совместимости с текущим публичным API Dos.Zone и предел `3 q2ded + 2 q2`.

## Решение

Dedicated-серверы показываются в той же вкладке `Custom`, что и обычные комнаты:

```text
комната Dos.Zone -> отдельный gateway -> случайный 127.0.0.1:port
                                      -> Q2PRO-X Custom
```

Транспорт, Q2PRO-X, WebRTC-NET, Quake II и Dos.Zone не меняются. Платформенные
адаптеры принимают `q2` и `q2ded`, а координаторы обслуживают пять независимых
слотов вместо двух. Три слота зарезервированы для `q2ded`, два — для `q2`.
Постоянный dedicated после отказа получает не более двух повторных запусков
gateway за одну сессию q2prox.

Новый общий runtime, новый протокол и новый внешний API не создаются.

## Причина текущей невидимости

Живой снимок 2026-09-03 содержал три `q2ded`-строки. Все три точных значения
`room` присутствовали в `/lookup`, но launcher принял `0/3`:

| q2prox сейчас | `q2ded` сейчас |
|---|---|
| `prefix=q2` | `prefix=q2ded` |
| требует `roomReady` | поля нет |
| требует `rtcServer` | поля нет |
| строит alias `q2.<owner>` | `room` является зарегистрированным alias |
| использует `owner` | `owner=0` у всех dedicated |

Шлюз не является причиной. Linux gateway с точным `room.q2ded.*` уже проходил
Quake handshake, `status` и вход в карту. Windows transport принимает ту же
общую грамматику безопасного alias.

## Цели и границы

Цели:

- показать до трёх dedicated и до двух обычных комнат;
- использовать настоящий Quake `status`: имя, карту, игроков и задержку;
- позволить `Disconnect -> Refresh -> другой сервер` без перезапуска Q2PRO-X;
- сохранить изоляцию отказов и границу учётных данных;
- одинаково проверять внешний JSON на Linux и Windows.

Не входит:

- новый transport или общий gateway для нескольких комнат;
- изменение Q2PRO-X, CFG/PAK, Quake protocol, Dos.Zone или браузерной игры;
- синтез либо подмена `status`;
- бесконечное восстановление stale alias;
- масштабирование сверх пяти комнат.

## Нормализованный контракт

`JoinTarget` — логическая форма, не новый класс или библиотека. Python и
PowerShell сохраняют маленькие реализации и проходят общие fixtures.

```text
roomId       безопасный идентификатор каталога
kind         q2 | q2ded
alias        точный HumbleNet alias
iceServers   1..16 свежих проверенных ICE entries
map          безопасное имя карты
game         всегда 3zb2
ordered      всегда false
name         только отображение
players      0..maxPlayers
maxPlayers   1..64
```

В coordinator уходит прежний compact room JSON. Для `q2ded` `roomId` является
и coordinator-facing identity: он уникален, начинается с `room.q2ded.` и
укладывается в существующий предел 255 байт. Хеши и generation tokens не нужны.

### Legacy `q2`

Сохраняется нынешний контракт: `prefix=q2`, `roomReady=true`, alias
`q2.<owner>`, одна точная RTC row по `rtcServer`, допустимые `game/profile`
равны `3zb2`, допустимый `ordered` равен `false`.

### Совместимый `q2ded`

Строка принимается только если:

- `prefix == q2ded`;
- `room` — безопасный token до 255 байт с префиксом `room.q2ded.`;
- точный `room` присутствует в свежем `/lookup` с учётом регистра;
- `name`, `map`, `players`, `maxPlayers` проходят существующие ограничения;
- `players < maxPlayers` при заполнении нового слота.

Для маршрутизации `alias = room`. Текущий producer передаёт один
`NET_SERVER_NAME` q2ded и room agent, а живой exact lookup подтверждает те же
строки. `owner`, `roomReady`, `rtcServer`, `updatedAt`, status `version=108` и
региональный суффикс не используются. `game=3zb2` и `ordered=false` остаются
локальными инвариантами продукта.

### ICE для `q2ded`

Отдельного RTC selector нет, поэтому адаптер использует все строки свежего
`/rtc/servers` в порядке ответа:

1. валидирует каждую row и ICE entry существующими правилами;
2. разворачивает entries в один список;
3. удаляет точные дубликаты, сохраняя первый;
4. требует итог `1..16` entries;
5. требует compact start JSON не более 65 535 байт.

Live-ответ 2026-09-03 содержал 14 уникальных entries. Если ответ вырастет или
станет невалидным, `q2ded` скрывается fail-closed; legacy `q2` продолжает
работать. Значения ICE/TURN не выводятся и не сохраняются.

При каждом успешном опросе конфигурация удержанного `q2ded`-слота пересобирается
из свежего RTC-ответа. Работающий gateway игнорирует heartbeat той же комнаты,
но recovery start получает свежий JSON. Ошибка RTC не отправляет новую команду
и не останавливает уже работающие gateway.

## Пять слотов

```text
0..2  q2ded
3..4  q2
```

Правила:

1. Живой корректный слот сохраняет номер.
2. Отсутствующая строка очищается после двух успешных опросов.
3. Новые кандидаты внутри пула сортируются по имени без учёта регистра, затем
   по `roomId`.
4. Полная комната не занимает новый слот, но живой слот сохраняется.
5. Комната одного вида не вытесняет комнату другого вида.
6. Строки сверх `3+2` не запускают процессы.
7. Каждый пул имеет собственный ограниченный перебор кандидатов; плохие карты
   dedicated не лишают обычные `q2` комнаты content checks.

Это экспериментальный предел. Его увеличение требует измерений ресурсов на
обеих платформах.

## Изменение карты

При той же комнате изменение `map` заново запускает content checker. Если карты
нет, endpoint снимается и gateway слота останавливается. Если карта доступна,
живой gateway не перезапускается; новый config понадобится при следующем
штатном старте слота. Имя, число игроков и RTC snapshot живой процесс не
перезапускают: пользовательские данные приходят из настоящего `status`.

Planner хранит проверенное имя карты вместе со слотом. При успешной смене карты
он обновляет сохранённые map/config; последующий recovery обязан использовать
их. Это состояние не сохраняется между запусками q2prox.

## Lifecycle dedicated

Для `q2` tombstone-модель не меняется. Для `q2ded` authoritative generation
нет, поэтому используется ограниченная совместимость:

- initial start не расходует бюджет;
- после `ROOM_CLOSED`, pre-ready или terminal failure endpoint снимается и
  gateway очищается;
- следующий 15-секундный heartbeat может снова запустить тот же `roomId`;
- допускаются два recovery start за сессию q2prox и один slot binding;
- успешная readiness не сбрасывает бюджет;
- после исчерпания tombstone действует до очистки строки, другого `roomId` или
  перезапуска q2prox.

Это ловит быстрый stop/start между опросами, но не создаёт вечный цикл на stale
alias. После двух неудачных восстановлений пользователь перезапускает q2prox.
Будущий authoritative route generation сможет заменить этот бюджет без
изменения gateway.

Выход Q2PRO-X или hard-kill владельца очищает все пять gateway. Закрытие одного
dedicated не закрывает игру и соседние комнаты.

## Безопасность

- catalog, lookup и RTC проверяются до запуска процесса;
- timeout, redirect и response-size policies не ослабляются;
- endpoints остаются loopback high ports;
- процессы остаются в Windows Job Object или Linux process group;
- ICE/TURN существуют только в памяти/pipe/memfd сессии;
- credentials не попадают в argv, env, настройки, source или логи;
- ошибка одной строки не скрывает корректные строки другого типа;
- невалидный top-level ответ сохраняет уже работающие slots.

## Пользовательский опыт

Пользователь запускает q2prox-dz как обычно. Q2PRO-X открывает
`Join Online -> Custom`; дополнительного окна и ручной настройки source нет.
После `Refresh` видны обычные и dedicated-серверы. Q2PRO-X получает настоящее
имя, карту, игроков и ping через Quake `status`.

После остановки сервера строка исчезает, но игра остаётся открытой. Пользователь
выбирает другой сервер. Вернувшийся dedicated появляется после обновления
source/`Refresh`, если recovery budget не исчерпан.

## Изменяемая поверхность

- общие catalog fixtures и два platform adapter;
- Linux managed alias validator;
- slot constants/parsers и один recovery counter в двух coordinators;
- lifecycle tests, ADR 0004, пользовательская и release-документация.

Gateway transport, WebRTC-NET и Q2PRO-X не меняются.

## Проверочные ворота

До кода:

1. хотя бы один `q2ded`; exact `room` найден в `/lookup`;
2. RTC flatten/dedupe даёт `1..16`, config `<=65535`;
3. существующий Linux gateway с этим alias и полным RTC payload проходит OOB
   `ping/ack` и `status`.

Пункт 3 обязателен: старое доказательство с одной RTC row не заменяет проверку
нового агрегированного payload.

До выпуска:

1. общие fixtures проходят на Linux/Windows; legacy `q2` не меняется;
2. fake lifecycle доказывает `3+2`, независимое закрытие, две recovery attempts,
   окончательный tombstone и hard-kill cleanup;
3. ротация карты повторяет content check;
4. Linux live: status, map entry, действие, переключение и isolated close;
5. Windows live: те же действия для dedicated и обычной комнаты;
6. в штатном состоянии Q2PRO-X открыт на вкладке `Custom`; за 60 секунд после
   прогрева пять idle gateway-деревьев без учёта процесса игры используют
   медианно не более 75% одного логического CPU и не более 1 GiB private/RSS
   суммарно; нет устойчивого роста handles/threads, paging pressure или orphan;
7. финальные архивы проходят штатную сборку и smoke из новой распаковки.

## Выпуск и откат

Изменение выпускается следующим release candidate после обеих платформенных
проверок. Предыдущая версия остаётся откатным архивом. Настройки не меняются,
миграция не нужна; старые клиенты просто игнорируют `q2ded`.

## Итог

Дизайн готов к реализации без внешнего изменения Dos.Zone. Ограниченный режим
совместимости использует текущую публичную связь `q2ded room == alias`, весь
валидный RTC payload и два bounded recovery start. Это минимальная правка с
понятным upgrade seam для будущего versioned join descriptor.
