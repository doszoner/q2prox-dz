# Design

[Handoff: продолжение на Windows](../../../docs/verification/2026-10-18-nearest-turn-windows-handoff.md).

Статус: реализовано в исходниках; Python и PowerShell Core проверены компонентно.
Linux-сценарий через обычный Hub завершён: список, Refresh, вход, смена карты
без перезапуска клиента и штатный Quit. Windows-проверки переданы пользователю
Windows и остаются открытыми. Функциональный контракт не меняется.
План уточнён 2026-10-18. См. [proposal](proposal.md), [tasks](tasks.md) и
[ресурсные ограничения](../../../docs/TURN-RESOURCE-POLICY.md).

## Context

До этого изменения `_ice_snapshot` и `Get-Q2DzDedicatedIceServers` объединяли
весь RTC-каталог. Общий шлюз поддерживает соединения ради готовности `Custom`.
Количество URL нельзя считать точным числом TURN allocations. TCP latency
не измеряет игровой RTT, доступность UDP или свободную квоту сервера.

## Goals / Non-Goals

Дать обеим платформам одинаковый ограниченный набор RTC-строк и сохранять
свежесть credentials. Не вводить лимит connections в этом изменении, не
менять контракт READY и не обещать устранения исчерпания TURN-квоты.

## Decisions

1. Полностью проверить RTC-ответ до отбора; отклонять дубликаты domain как
   неоднозначный выбор; идентичность domain и override — ASCII lowercase. Выбирать все ICE записи первой строки и только URL
   со схемой `turn:`/`turns:` из записей второй. Не использовать позицию
   `iceservers[1]`. В смешанной записи второй строки сохранить credentials,
   отфильтровать STUN URL; пустую запись отбросить. Затем штатная дедупликация
   и существующие лимиты количества/64 KiB. Новые публичные поля не вводятся.
2. Медиана успешных TCP-connect к `domain:3478`, до трёх попыток, таймаут
   попытки 1 с. Недоступность — отдельное состояние, не число 999.
   Измеренные строки идут раньше недоступных; равенство и все ошибки
   разрешаются исходным порядком. Один успешный замер допустим.
   DNS разрешается один раз на domain и не входит в TCP latency. Одна попытка
   делит общий таймаут между всеми возвращёнными IP-адресами. Успешные попытки
   до deadline сохраняются, незавершённые не добавляют samples; медиана двух —
   их среднее. TCP 3478 может быть закрыт и у работоспособного TURN — это эвристика.
3. Монотонный бюджет измерений — 3 с, не более четырёх активных domain.
   Бюджет включает запуск worker, DNS и очередь. Измерение изолировано в одном
   короткоживущем процессе: Python использует четыре потока внутри worker,
   Windows PowerShell — до четырёх runspace внутри worker. Родитель завершает
   процесс по deadline, не ждёт DNS и сохраняет только samples до cutoff.
   Не начавшиеся domain остаются недоступными. Ожидание завершения worker ограничено по времени;
   cleanup и планировщик ОС добавляют задержку, поэтому это не hard real-time
   гарантия возврата за 3.000 с. Сам запуск процесса не является отменяемым API.
   Между выборами resolver tasks не сохраняются. Worker получает только
   hostname/index и возвращает числа; RTC-ответы и credentials ему не передаются.
   На Linux механизм проверен с injected stuck DNS; PowerShell Core проверен
   отдельно, Windows PowerShell 5.1 пока не проверен.
4. Кэш хранит только domain первой и второй строк, не credentials. Изменение
   порядка ответа не меняет выбор. Исчезновение выбранного domain запускает
   новый выбор. Новый ICE-снимок сохраняет текущую семантику generation:
   штатные heartbeat PUT launcher→coordinator сохраняются; DROP не возникает,
   активный gateway target не получает новый PUT/ID и не пересоздаётся. Если
   каталог вырос с одной строки, первый domain сохраняется, второй выбирается
   среди остальных. Кэш меняется
   лишь после проверки нового выбранного ICE-снимка.
5. Валидный `Q2DZ_RTC_SERVER` из ответа становится первым без измерения;
   вторым — первый другой domain в порядке ответа. Не найденный/невалидный
   override даёт только `ICE_OVERRIDE result=missing|invalid` и обычный выбор.
   Неустановленное/пустое значение не даёт диагностики. `missing` означает,
   что непустой валидный domain не найден. Значение переменной не логируется.
   Проверка hostname общая с RTC domain. Если override появился в последующем
   ответе, он имеет приоритет над прежним fallback-кэшем; уже выбранный override
   сохраняет свой backup при перестановке ответа.
6. Коннектор и часы подменяются в существующих тестах; общие fixtures содержат
   успешные/неуспешные результаты, а не настоящие сетевые endpoints.

## Risks / Trade-offs

Второй TURN может участвовать в gathering сразу и тоже расходовать quota.
Ближайший TCP-сервер может иметь худший UDP путь или быть перегруженным.
Если все измерения не удались, берутся первые две строки: это деградация
доступности относительно полного списка, а не гарантия «не хуже».
Измерение не должно блокировать игровой поток или перезапускать рабочую связь.

## Local verification

Общие fixtures и тесты обеих платформ: выбор, ошибки/DNS deadline, cache,
credentials, размеры, смешанные ICE URL и override. Затем обычный Hub с
локальными изменёнными launcher: список и вход в комнату, свежие credentials
без пересоздания маршрута. Подробный runbook и результаты — локально вне Git.
Без метрик оператора число TURN allocations не проверяется; фиксировать это
ограничение, не заменять его количеством candidate-строк.

Python и PowerShell Core на Linux прошли компонентные проверки; Core не служит
доказательством Windows PowerShell 5.1. Windows-проверки здесь пропускаются и
передаются пользователю: общие fixtures, deadline/завершение worker, launcher
stdin и полный сценарий обычного Hub. Команды и критерии — в
[Windows checklist](tasks.md#windows-checklist). Linux-сценарий завершён в фоне:
Custom, ручной Refresh, вход в управляемую комнату, q2dm1 → q2dm2 с сохранением
PID клиента и штатный Quit. Обновление credentials без пересоздания активного
target подтверждено компонентными проверками, не принудительной live-ротацией.
Сводка результатов, очистки и инструкции для Windows — в handoff выше. Gameplay
принимает пользователь; непроверенные Windows-пункты не считаются PASS.
