# Design

Статус: предложение; реализация не начата. Исходный план от 2026-10-13
исправлен 2026-10-18. См. [proposal](proposal.md) и
[ресурсные ограничения](../../../docs/TURN-RESOURCE-POLICY.md).

## Context

Текущий `_ice_snapshot` и `Get-Q2DzDedicatedIceServers` объединяют весь
RTC-каталог. Общий шлюз поддерживает соединения ради готовности `Custom`.
Количество URL нельзя считать точным числом TURN allocations. TCP latency
не измеряет игровой RTT, доступность UDP или свободную квоту сервера.

## Goals / Non-Goals

Дать обеим платформам одинаковый ограниченный набор RTC-строк и сохранять
свежесть credentials. Не вводить лимит connections в этом изменении, не
менять контракт READY и не обещать устранения исчерпания TURN-квоты.

## Decisions

1. Полностью проверить RTC-ответ до отбора; отклонять дубликаты domain как
   неоднозначный выбор. Выбирать все ICE записи первой строки и только URL
   со схемой `turn:`/`turns:` из записей второй. Не использовать позицию
   `iceservers[1]`. В смешанной записи второй строки сохранить credentials,
   отфильтровать STUN URL; пустую запись отбросить. Затем штатная дедупликация
   и существующие лимиты количества/64 KiB. Новые публичные поля не вводятся.
2. Медиана успешных TCP-connect к `domain:3478`, до трёх попыток, таймаут
   попытки 1 с. Недоступность — отдельное состояние, не число 999.
   Измеренные строки идут раньше недоступных; равенство и все ошибки
   разрешаются исходным порядком. Один успешный замер допустим.
   TCP 3478 может быть закрыт и у работоспособного TURN — это эвристика.
3. Общий deadline выбора 3 с, не более четырёх параллельных измеряемых domain.
   Deadline включает DNS и очередь; неуспевшие строки считаются недоступными.
   Нельзя реализовать deadline через ожидание завершения executor с зависшим
   системным DNS. До реализации проверить отмену/ограниченное завершение на
   Python и Windows PowerShell 5.1; если это недостижимо выбранным API,
   уточнить механизм в дизайне, а не обещать ложную границу времени.
4. Кэш хранит только domain первой и второй строк, не credentials. Изменение
   порядка ответа не меняет выбор. Исчезновение выбранного domain запускает
   новый выбор. Новый ICE-снимок сохраняет текущую семантику generation:
   активная комната не получает DROP/PUT лишь из-за новых credentials.
5. Валидный `Q2DZ_RTC_SERVER` из ответа становится первым без измерения;
   вторым — первый другой domain в порядке ответа. Отсутствующий/невалидный
   override даёт только `ICE_OVERRIDE result=missing|invalid` и обычный выбор.
   Значение переменной не логируется. Проверка hostname общая с RTC domain.
6. Коннектор и часы подменяются в существующих тестах; общие fixtures содержат
   успешные/неуспешные результаты, а не настоящие сетевые endpoints.

## Risks / Trade-offs

Второй TURN может участвовать в gathering сразу и тоже расходовать quota.
Ближайший TCP-сервер может иметь худший UDP путь или быть перегруженным.
Если все измерения не удались, берутся первые две строки: это деградация
доступности относительно полного списка, а не гарантия «не хуже».
Измерение не должно блокировать игровой поток или перезапускать рабочую связь.

## Local verification

Общие fixtures и тесты обеих платформ: выбор, ошибки/DNS deadline, cache,
credentials, размеры, смешанные ICE URL и override. Затем обычный Hub с
локальными изменёнными launcher: список и вход в комнату, свежие credentials
без пересоздания маршрута. Подробный runbook и результаты — локально вне Git.
Без метрик оператора число TURN allocations не проверяется; фиксировать это
ограничение, не заменять его количеством candidate-строк.
